# 3️⃣ Junction Object: CampaignMember

This is **one of the most important junction objects**.

It connects:

```
Campaign
    ↕
CampaignMember
    ↕
Lead OR Contact

Because:

```
One Campaign → many leads
One Lead → many campaigns

That means **many-to-many relationship**.

Salesforce solves this using **CampaignMember**.

Fields

```

ContactId

```

Rule

```

```

Example

## 1️⃣ Polymorphic Relationships in Salesforce (Deep Explanation)

A **polymorphic relationship** means **one field can reference multiple object types**.
Instead of pointing to **one specific object**, the field can point to **different objects depending on the record**.

This concept appears in **Activities, Email, and some other system objects**, and it is **very important for Apex and SOQL**.

---

# 1️⃣ Why Salesforce Created Polymorphic Relationships

Normally a lookup field connects to **one object only**.

Example:

```
Contact.AccountId → Account
```

But sometimes Salesforce needs **one field to connect to multiple objects**.

Example:

A **Task** could be related to:

* Lead
* Contact
* Account
* Opportunity
* Case
* Custom Object

Creating separate fields for each would be messy, so Salesforce uses **polymorphic fields**.

---

# 2️⃣ Main Polymorphic Fields in Salesforce

| Field              | Used In             | Can Reference                              |
| ------------------ | ------------------- | ------------------------------------------ |
| **WhoId**          | Task, Event         | Lead, Contact                              |
| **WhatId**         | Task, Event         | Account, Opportunity, Case, Custom Objects |
| **ParentId**       | EmailMessage        | Many objects                               |
| **LinkedEntityId** | ContentDocumentLink | Any record                                 |
| **OwnerId**        | Many objects        | User, Queue                                |

---

# 6️⃣ How Salesforce Stores This Internally

Polymorphic fields store **record ID**.

Salesforce IDs contain **prefixes identifying object type**.

Example prefixes:

| Object      | ID Prefix |
| ----------- | --------- |
| Account     | 001       |
| Contact     | 003       |
| Opportunity | 006       |
| Lead        | 00Q       |

Example

```
WhoId = 0038A00000ABC123
```

Prefix **003 → Contact**

So Salesforce knows the record type.

---

# 7️⃣ SOQL Queries Using Polymorphic Fields

Salesforce allows **TYPEOF queries**.

Example:

```sql
SELECT Subject,
TYPEOF What
 WHEN Account THEN Name
 WHEN Opportunity THEN Amount
END
FROM Task
```

This checks the **actual object type**.

---

# 8️⃣ Query Activities for Opportunity

Example:

```sql
SELECT Id, Subject, WhoId, WhatId
FROM Task
WHERE WhatId = '006ABC123'
```

Returns all tasks related to the opportunity.

---

# 9️⃣ Query Contact Activities

Example:

```sql
SELECT Id, Subject
FROM Task
WHERE WhoId = '003XYZ456'
```

Returns activities related to that contact.

---

# 🔟 Important Limitation

Polymorphic fields **cannot be used in all relationship queries**.

Example (not allowed):

```sql
SELECT Who.Name
FROM Task
```

Instead you must query the object separately.

# 1️⃣ Big Picture: Salesforce Access Architecture

Security in Salesforce works in **3 layers**.

```text
Authentication → Authorization → Data Access
```

Flow:

```text
User
 ↓
Profile
 ↓
Permission Sets
 ↓
Role Hierarchy
 ↓
Sharing (Groups / Queues / Rules)
```

So the main objects are:

| Layer             | Objects       |
| ----------------- | ------------- |
| Identity          | User          |
| Base Permissions  | Profile       |
| Extra Permissions | PermissionSet |
| Record Visibility | UserRole      |
| Sharing           | Group, Queue  |

# 1️⃣ SOQL Relationship Basics

There are **two directions in SOQL**.

### Parent → Child (Subquery)

Uses **child relationship name**

```sql
SELECT Id, Name,
       (SELECT Id, LastName FROM Contacts)
FROM Account
```

---

### Child → Parent (Dot Notation)

Uses **lookup field**

```sql
SELECT Id, Name, Account.Name
FROM Contact
```
