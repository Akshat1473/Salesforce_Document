## 🚀 Apex Basics: Quick Summary

### **Code Kya Hai?**

Code insaano aur computers ke beech ki ek **bhasha (language)** hai. Jaise ek recipe mein step-by-step instructions hote hain khana banane ke liye, waise hi code computer ko precise instructions deta hai tasks perform karne ke liye.

### **Pseudocode: Planning ki Pehli Seedhi**

Asli code likhne se pehle hum **Pseudocode** likhte hain. Yeh normal English (ya kisi bhi language) mein likha gaya ek plan hota hai jo step-by-step batata hai ki program kya karega.

* **Kyun zaroori hai?** Taaki non-programmers bhi samajh sakein ki kya logic build ho raha hai aur koi step miss na ho.

### **Code Commenting: Kyun aur Kaise?**

Comments wo notes hote hain jo developers apne liye ya doosre developers ke liye chhodte hain. Computer inko **ignore** kar deta hai; ye sirf readability ke liye hote hain.

1. **Single Line Comment:** Iske liye `//` use hota hai.
* *Example:* `// Yeh ek single line comment hai`

2. **Multiline Comment:** Iske liye `/*` se shuru aur `*/` se khatam karte hain.
* *Example:*

Apex collections (specifically **Lists**) ka concept bahut simple hai. Socho ki aapke paas ek bag hai jisme aap ek hi tarah ki cheezein (jaise sugar cubes ya shopping items) store kar sakte ho.

Yahan Apex Lists ka breakdown aur important methods diye gaye hain:

## 1. List Kya Hai?

List ek "Ordered Collection" hai. Iska matlab hai ki items ek sequence mein hote hain aur har item ka ek unique number hota hai jise **Index** kehte hain.

> **Imp Note:** Programming mein ginti hamesha **0** se shuru hoti hai, 1 se nahi.

---

## 2. List Declare aur Initialize Kaise Karein?

Aap teen tarike se list bana sakte hain:

* **Empty List Banana:**
`List<String> groceries = new List<String>();`
* **Direct Value Ke Saath (Curly Braces):**
`List<String> groceries = new List<String>{'Tea', 'Sugar'};`
* **Fixed Size Ke Saath (Array Notation):**
`String[] groceries = new String[4];` (Isse 4 khaali slots ban jayenge).

---

## 3. Important Inbuilt Methods (Don't Skip)

Apex humein kuch ready-made methods deta hai list ke saath kaam karne ke liye:

| Method | Kaam Kya Hai? | Example |
| --- | --- | --- |
| **add(item)** | List ke end mein naya item jodne ke liye. | `groceries.add('Honey');` |
| **add(index, item)** | Kisi specific position par item daalne ke liye. | `groceries.add(0, 'Milk');` (Milk index 0 par aa jayega) |
| **get(index)** | Kisi specific index ki value dekhne ke liye. | `String item = groceries.get(1);` |
| **size()** | List mein total kitne items hain check karne ke liye. | `Integer count = groceries.size();` |
| **clear()** | List ke saare items delete karne ke liye. | `groceries.clear();` |
| **sort()** | Items ko alphabetical ya numerical order mein set karne ke liye. | `groceries.sort();` |

---

## 4. Important Example: Adding vs. Setting Size

Bahut se log yahan confuse hote hain. Agar aapne size pehle hi fix kar diya hai, toh `add()` method list ka size badha deta hai.

**Example Code:**

```java
String[] groceries = new String[2]; // Size 2 hai (null, null)
groceries.add('Tea'); 
// Ab list ka size 3 ho gaya! [null, null, 'Tea']
// Kyunki add() hamesha end mein jotta hai.

```

Agar aapko pehle box (index 0) mein value daalni hai, toh aapko index use karna chahiye:
`groceries[0] = 'Tea';`

---

## 5. Quiz Review (Logic)

Aapne jo quiz dekha, uske logic samajhte hain:

1. **Creating List:** `List<String> sports = new List<String>();` ya `String[] sports = new String[3];`
2. **Referencing Item:** Agar list hai `{'Soccer', 'Baseball', 'Golf', 'Tennis'}`, toh 'Golf' ka index **2** hoga (0: Soccer, 1: Baseball, 2: Golf). Code hoga: `sports[2]`.

Salesforce Apex mein **Set** aur **Map** do bahut hi powerful collections hain jo aapke code ko fast aur efficient banate hain. Aaiye inhein asaan bhasha (Hinglish) mein samajhte hain:

---

## 1. Set (The "Unique" Collection)

Set ek aisa bag hai jisme **duplicates allow nahi hote**. Agar aap isme ek hi cheez do baar dalne ki koshish karenge, toh wo use ek hi baar count karega.

* **Unordered:** Isme items ka koi fixed order (sequence) nahi hota.
* **Unique Elements:** Sirf alag-alag values hi store hoti hain.
* **Case Sensitive:** String ke case mein 'Apple' aur 'apple' alag-alag maane jayenge.

### Set Declare aur Initialize:

```java
// Khali Set banana
Set<String> uniqueColors = new Set<String>();

// Value ke saath banana
Set<String> fruits = new Set<String>{'Apple', 'Banana', 'Apple'}; 
// Output: {'Apple', 'Banana'} -- Dusra 'Apple' delete ho jayega.

```

### Important Methods for Set:

| Method | Kaam Kya Hai? | Example |
| --- | --- | --- |
| **add(element)** | Naya item add karne ke liye. | `fruits.add('Mango');` |
| **contains(element)** | Check karne ke liye ki item set mein hai ya nahi. | `fruits.contains('Apple');` // returns true |
| **remove(element)** | Kisi item ko delete karne ke liye. | `fruits.remove('Banana');` |
| **size()** | Total unique items check karne ke liye. | `fruits.size();` |

---

## 2. Map (The "Key-Value" Pair)

Map sabse zyada use hone wala collection hai. Ye ek **Phone Book** ki tarah hai, jahan ek **Name (Key)** hota hai aur uska ek **Phone Number (Value)** hota hai.

* **Key:** Hamesha unique hoti hai (e.g., Student ID).
* **Value:** Duplicate ho sakti hai (e.g., Do students ka naam same ho sakta hai).
* **Efficient:** Key ki madad se value ko bahut jaldi dhoonda ja sakta hai.

### Map Declare aur Initialize:

```java
// Map<KeyType, ValueType>
Map<Integer, String> studentMap = new Map<Integer, String>();

// Values add karna (put method)
studentMap.put(101, 'Rahul');
studentMap.put(102, 'Amit');
studentMap.put(101, 'Vijay'); // 101 pe ab 'Vijay' ho jayega, Rahul overwrite ho jayega.

```

### Important Methods for Map:

| Method | Kaam Kya Hai? | Example |
| --- | --- | --- |
| **put(key, value)** | Key aur Value ka pair add karne ke liye. | `map.put('IN', 'India');` |
| **get(key)** | Key ka use karke value nikalne ke liye. | `String c = map.get('IN');` // 'India' |
| **containsKey(key)** | Check karne ke liye ki wo key map mein hai ya nahi. | `map.containsKey('US');` |
| **keySet()** | Saari keys ko ek **Set** mein nikalne ke liye. | `Set<String> keys = map.keySet();` |
| **values()** | Saari values ko ek **List** mein nikalne ke liye. | `List<String> allValues = map.values();` |

---

## 3. Real-World Example: List vs Set vs Map

Maano aapke paas Accounts ki ek list hai:

1. **List:** `[Acc1, Acc2, Acc3, Acc1]` (Duplicate allow hain, order fix hai).
2. **Set:** `[Acc1, Acc2, Acc3]` (Duplicates hata diye, sirf unique IDs rakhne ke liye best hai).
3. **Map:** `{Acc1.Id => Acc1, Acc2.Id => Acc2}` (Id se Account record ko turant find karne ke liye best hai).

---

### Important Tip:

Salesforce Trigger mein hum aksar `Trigger.newMap` use karte hain jo hamein Records ki ID aur unka pura Data ek Map mein deta hai, taaki humein loop ke andar baar-baar search na karna pade.

//Control Flow 
Apex mein code ka flow control karne ke liye hum **Decision Making** statements ka use karte hain. Iska matlab hai ki computer kab kaunsa kaam karega, ye kuch conditions par depend karta hai.

Aaiye ise hinglish mein aur simple tarike se samajhte hain:

---

## 1. Comparison Operators (Tulna Karne Wale)

Decision lene se pehle hum do cheezon ko compare karte hain. Iska result hamesha **Boolean** (True ya False) hota hai.

| Operator | Meaning | Example | Result |
| --- | --- | --- | --- |
| `==` | Barabar hai? | `10 == 10` | True |
| `!=` | Barabar nahi hai? | `10 != 5` | True |
| `>` | Bada hai? | `20 > 10` | True |
| `<` | Chhota hai? | `5 < 10` | True |
| `>=` | Bada ya barabar? | `10 >= 10` | True |

> **Dhyan Dein:** `=` ka matlab hota hai value dena (Assign), aur `==` ka matlab hota hai check karna (Compare).

---

## 2. If-Else Statements

Ye sabse basic decision-making tool hai.

* **If-Else:** Jab sirf do hi raste hon. "Agar barish hui toh umbrella lo, nahi toh mat lo."
* **If-Else If-Else:** Jab do se zyada options hon.

**Example:**

```java
String waterLevel = 'half';

if(waterLevel == 'empty') {
    System.debug('Kettle bharo');
} else if(waterLevel == 'half') {
    System.debug('Thoda aur paani daalo');
} else {
    System.debug('Kettle full hai');
}

```

---

## 3. Switch Statement (Smart Choice)

Jab aapke paas ek hi variable ki bahut saari alag-alag values check karni hon, toh `switch` use karna zyada saaf (clean) lagta hai.

```java
switch on waterLevel {
    when 'empty', 'half' { 
        System.debug('Paani bharo');
    }
    when 'full' {
        System.debug('Chai banao');
    }
    when else {
        System.debug('Error!');
    }
}

```

---

## 4. Logical Operators (AND aur OR)

Kabhi-kabhi ek decision lene ke liye do conditions check karni padti hain.

* **AND (`&&`):** Dono conditions true honi chahiye. (e.g., Chai patti BHI honi chahiye AUR doodh BHI).
* **OR (`||`):** Koi bhi ek condition true ho jaye toh kaam ban jayega. (e.g., Chai mil jaye YA Coffee mil jaye).

**Example (Redundant code hatane ke liye):**

```java
// Purana tarika (Redundant)
if(water == 'empty') { fill(); }
else if(water == 'half') { fill(); }

// Naya Smart Tarika (Using OR)
if(water == 'empty' || water == 'half') {
    fill(); // Ek hi baar likhna pada!
}

```

---

## 5. Quiz Solutions (Logic)

Aapke quiz ke answers ka logic ye hai:

1. **Result Variable:** `Integer i = 44; Boolean result = i < 20;`
* Yahan check ho raha hai: Kya 44 chhota hai 20 se? **Jawab: False.**


2. **Options in If-Else:** Ek basic `if-else` statement mein hamesha **2 options** hote hain (ek `if` wala aur ek default `else` wala).

Apex mein loops ka use repetitive tasks ko handle karne ke liye kiya jata hai. Yahan sabhi loops ke short examples aur unka logic diya gaya hai:

### 1. While Loop

Jab aapko ye nahi pata ki loop kitni baar chalega, bas ek **condition** pata ho. Ye pehle condition check karta hai, phir execute hota hai.

```java
Integer count = 1;
while (count <= 3) {
    System.debug('Count is: ' + count);
    count++; // Value badhana zaroori hai nahi toh infinite loop ho jayega
}
// Output: 1, 2, 3

```

### 2. Do-While Loop

Ye loop **kam se kam ek baar** zaroor chalta hai, chahe condition shuru mein hi galat kyun na ho, kyunki condition baad mein check hoti hai.

```java
Integer i = 10;
do {
    System.debug('Run hua: ' + i);
    i++;
} while (i < 5); 
// Output: Run hua: 10 (Ek baar chala phir ruk gaya kyunki 11 < 5 false hai)

```

### 3. Standard For Loop

Jab aapko fix pata ho ki loop **kitni baar** chalana hai. Initialization, Condition, aur Increment sab ek hi line mein hota hai.

```java
for (Integer i = 1; i <= 3; i++) {
    System.debug('Number: ' + i);
}
// Output: 1, 2, 3

```

### 4. For-Each Loop (List/Collection Loop)

Salesforce mein sabse zyada use hone wala loop. Ye kisi **List** ya **Set** ke har ek item par automatic iterate karta hai.

```java
List<String> teaTypes = new List<String>{'Green', 'Black', 'Masala'};

for (String tea : teaTypes) {
    System.debug('Available Tea: ' + tea);
}
// Output: Green, Black, Masala

```

---

**Summary Table:**
| Loop | Best Use Case |
| :--- | :--- |
| **While** | Jab tak condition true hai (Check first). |
| **Do-While** | Kam se kam 1 baar run karne ke liye. |
| **For** | Jab counting (1 to N) karni ho. |
| **For-Each** | List ya Records ke saath kaam karne ke liye. |

//OBJECTS AND CLASSES
Ab hum Apex ke sabse main concept ki taraf badh rahe hain: **Object-Oriented Programming (OOP)**. Iska matlab hai ki hamara code "Objects" ke baare mein baat karta hai.

Aaiye ise hinglish mein aur simple examples ke saath samajhte hain:

---

## 1. Class vs Object (Blueprint vs Ghar)

In dono ka rishta ek **Blueprint** aur usse bane **Ghar** jaisa hai.

* **Class (The Blueprint):** Ye ek naksha hai. Isme bataya jata hai ki ek object kaisa dikhega aur kya kaam karega. Jaise `Flower` class batati hai ki har phool ka ek `color` hoga aur wo `grow()` kar sakega.
* **Object (The Instance):** Ye asli cheez hai jo blueprint se bani hai. Ek `Flower` class se aap `Rose`, `Tulip`, aur `Lily` naam ke alag-alag objects bana sakte hain.

---

## 2. Variables aur Methods

Class ke andar do hi main cheezein hoti hain:

1. **Variables (Characteristics):** Wo cheez jo object ko describe karti hai. (Example: `String color;`, `Integer height;`).
2. **Methods (Behaviors):** Wo kaam jo object kar sakta hai. (Example: `void grow()`, `void wilt()`).

---

## 3. Parameters (Variable Placeholder)

Kabhi-kabhi humein method ko batana padta hai ki use kaise kaam karna hai. **Parameter** ek khali jagah (placeholder) hoti hai jo kisi value ka intezar karti hai.

**Example:**
`public void wilt(Integer numberOfPetals)`
Yahan `numberOfPetals` ek parameter hai. Jab aap method call karenge `wilt(4);`, toh wo 4 number is parameter mein chala jayega.

---

## 4. Return Types (Jawab Milna)

Jab aap kisi method ko bulate hain, toh wo do kaam kar sakta hai:

1. **Void:** Kaam karke chup baith jayega, kuch wapas nahi dega. (Jaise waiter ko pani lane bola, wo pani dekar chala gaya).
2. **Data Type (Integer, String, etc.):** Kaam karne ke baad aapko ek **Value** wapas karega. Iske liye `return` keyword use hota hai.

**Example:**

```java
public Integer getPetalCount() {
    return 10; // Ye method 10 wapas karega
}

```

---

## 5. Object Kaise Banate Hain?

Ek class se naya object banane ke liye hum `new` keyword ka use karte hain.

```java
// Syntax: ClassName objectName = new ClassName();
Flower tulip = new Flower(); 

// Dot notation se values dena
tulip.color = 'Yellow';
tulip.grow(); // Method call karna

```
## 6. Quiz Solutions (Logic)

1. **Return Type:** Kaunsa return type value wapas karta hai?
* **Logic:** `void` kuch wapas nahi karta. Agar method declaration mein `Integer`, `String`, ya `Boolean` likha hai, toh wo value return karega.


2. **Parameter Syntax:** Parameter define karne ka sahi tarika kya hai?
* **Logic:** Pehle **Data Type** likha jata hai, phir **Parameter Name**. Jaise: `(String colorName)` ya `(Integer count)`.

## 1. sObject Kya Hai? (Definition)

sObject ka full form **Salesforce Object** hota hai. Yeh Apex ka ek complex data type hai jo Salesforce ke database ke ek single record ko represent karta hai.

* **Relationship:** Har Salesforce object (jaise Account, Contact, ya Custom Object) Apex mein ek sObject type ki tarah behave karta hai.
* **Container Concept:** Agar variables ko ek "container" mana jaye, toh sObject ek aisa bada container hai jisme kayi chhote containers (fields) hote hain.
* **Data Types:** sObject ke andar alag-alag data types ke fields ho sakte hain, jaise String (Name), Date (Close Date), Integer (Number of Employees), ya Boolean (Active).

### Example:

`Account myAcct = new Account();`
Yahan `myAcct` ek Account sObject hai jo abhi khali hai.

---

## 2. sObjects vs Other Data Types

Apex ke normal data types (Primitive Types) aur sObjects mein bada farq hota hai:

| Feature | Primitive Data Types (String, Integer, etc.) | sObjects (Account, Contact, etc.) |
| --- | --- | --- |
| **Capacity** | Ek variable mein sirf ek hi value store karta hai. | Ek variable mein poora database record (multiple fields) store karta hai. |
| **Structure** | Iska koi internal structure nahi hota. | Iske properties (fields) hote hain jo database schema se match karte hain. |
| **Assignment** | `Integer x = 5;` | `Account a = new Account(Name='Test');` |

---

## 3. sObject Properties (Field Values)

Apex code mein Salesforce ke fields ko **Properties** kaha jata hai. Inhein handle karne ke liye **Dot Notation** ka use hota hai.

* **Set Field Value:** Kisi field mein value dalne ke liye dot notation ka use karein.
* `myAcct.Name = 'The Tea Factory';`


* **Get Field Value:** Kisi field se value nikalne ke liye bhi dot notation kaam aata hai.
* `String name = myAcct.Name;`



---

## 4. DML (Data Manipulation Language)

Sirf code mein sObject banane se wo database mein save nahi hota. Database mein records create, update, ya delete karne ke liye **DML** ka istemal kiya jata hai.

### Key DML Operations:

1. **Insert:** Naya record database mein create karta hai.
2. **Update:** Maujooda (existing) record mein badlav (changes) karta hai.
3. **Delete:** Database se record ko mita deta hai.

### Example Code:

```java
Account store = new Account();
store.Name = 'The Tea Factory';
insert store; // Yeh line database mein record create karegi

```

---

## 5. Bulkification (Efficiency and Limits)

Salesforce multi-tenant environment hai, isliye resource utilization par limits hoti hain. Ek execution context mein aap sirf **150 DML calls** kar sakte hain.

* **Problem:** Agar aap loop ke andar `insert` statement likhte hain aur loop 200 baar chalta hai, toh code fail ho jayega.
* **Solution (Bulkification):** Records ko pehle ek **List** mein jama (add) karein aur phir poori list ko ek hi DML statement se insert karein.
* **Benefit:** Isse aap ek hi DML call mein hazaaron records process kar sakte hain.

---

## 6. Loop ke sath sObjects aur Lists ka Use

Multiple records create karne ka sabse behtar tarika loop aur list ka combination hai:

1. Ek empty list banayein: `List<Account> accList = new List<Account>();`
2. Loop ke andar naya sObject banayein aur use list mein add karein: `accList.add(newAcct);`
3. Loop ke bahar single DML chalayein: `insert accList;`

---

**Summary for Notes:**

* **sObject:** Salesforce record ka Apex representation.
* **Dot Notation:** Fields ko access karne ka tarika (`object.field`).
* **DML:** Database interactions (`insert`, `update`, `delete`).
* **Bulkification:** Records ko lists mein collect karke process karna taaki Governor Limits cross na hon.


//SOQL
Salesforce mein **Relationship Queries** ka matlab hai ek hi query se do aise objects ka data nikalna jo aapas mein jude hue (related) hain. Isse humein do alag-alag queries nahi likhni padti.

---

## 1. Relationship Queries Kya Hain?

Normal SOQL query sirf ek object se data laati hai, lekin Relationship Query ka use karke hum related objects (jaise Account aur uske Contacts) ka data cross-object fetch kar sakte hain.

Yeh do tarah ki hoti hain:

1. **Child-to-Parent Query:** Child object se Parent ka data mangwana.
2. **Parent-to-Child Query:** Parent object se uske saare Children ka data mangwana.

---

## 2. Objects ki Relationship Identify Karna

Query likhne se pehle yeh pata hona chahiye ki Parent kaun hai aur Child kaun.

* **Master-Detail/Lookup:** Jis object par Lookup field hoti hai, wo **Child** hota hai. Jise wo point karta hai, wo **Parent** hota hai.
* **Example:** `Contact` par `AccountId` field hoti hai jo `Account` ko point karti hai. Iska matlab:
* **Account** = Parent
* **Contact** = Child



---

## 3. Child-to-Parent Query (Using Dot Notation)

Jab hum Child object par khade ho kar Parent ki details mangwate hain, toh hum **Dot (.) Notation** ka use karte hain.

* **Requirement:** "Saare Contacts ki list lao aur unke Account ka naam bhi dikhao."
* **Logic:** Query `Contact` se shuru hogi.
* **Syntax:** `SELECT Name, Account.Name FROM Contact`

Yahan `Account.Name` ka matlab hai: Contact ke upar jo Account lookup hai, uske andar jao aur wahan se `Name` field lekar aao.

---

## 4. Parent-to-Child Query (Using Subquery)

Jab hum Parent record ke saath uske saare related Children ki list chahte hain, toh hum **Subquery** ka use karte hain.

* **Subquery:** Ek SELECT statement ke andar dusra SELECT statement (brackets mein).
* **Important Rule:** Subquery mein hamesha **Child Relationship Name** (plural) ka use hota hai, object name ka nahi.
* **Requirement:** "Har Account ka naam lao aur uske saare related Contacts ke naam bhi lao."
* **Syntax:** `SELECT Name, (SELECT Name FROM Contacts) FROM Account`

**Dhyan dein:** Humne `FROM Contact` ki jagah `FROM Contacts` (plural) likha hai kyunki standard relationship name plural hota hai.

---

## 5. Subquery Se Filter Karna (Filtering)

Kabhi-kabhi humein Parent records ko filter karna hota hai unke Children ke data ke basis par. Ise **Semi-Join** bhi kehte hain.

* **Requirement:** "Sirf wahi Accounts lao jinke kisi Contact ka Last Name 'Forbes' hai."
* **Logic:** Hum `WHERE` clause mein ek subquery dalenge jo un Accounts ki IDs dhundegi jinke paas 'Forbes' wala contact hai.
* **Syntax:** ```sql
SELECT Name
FROM Account
WHERE Id IN (SELECT AccountId FROM Contact WHERE LastName = 'Forbes')
